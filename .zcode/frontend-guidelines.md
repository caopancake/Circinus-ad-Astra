# Frontend Guidelines

本文档只规定 Vue、TypeScript 和前端运行时的通用写法、通用设计判断、测试和交互代码规则。项目层级、能力所有权、业务状态、具体页面行为和调用链见 `.zcode/overview.md` 或所属模块文档。

## 类型与分支设计

- 组件文件使用 `PascalCase`；composable 使用 `use*`；store 文件使用 `*.store.ts`；类型使用 `PascalCase`。
- 不可信输入声明为 `unknown` 并显式收窄；禁止 `any`、`as any` 和用类型断言替代校验。
- 互斥且封闭的状态使用判别联合或明确的枚举类型；开放集合使用可扩展结构。
- TypeScript 的 `enum`、字符串联合和常量对象必须按值域与运行时需求选择：需要运行时枚举、跨边界稳定标识或与 Rust enum 对应时使用 enum；只需静态封闭类型时使用联合类型；需要运行时映射且保留字面值时使用常量对象。
- 枚举、联合类型和常量对象的选择必须在同一类问题中保持一致；禁止同一值域在不同模块使用多套表达。
- 多分支处理先判断同构程度：输入、输出、状态和生命周期一致时优先使用一个统一分派函数。
- 分支拥有不同不变量、错误语义或生命周期时，必须拆为分别命名的函数；表面参数相似不能单独证明可以合并。
- 抽取 helper、adapter、composable、hook 或参数化函数前，必须证明共享不变量成立，并且能减少公开入口、状态 owner 或重复生命周期逻辑。
- 同类问题优先复用已有同类实现，并保持同类模块的结构一致；领域差异必须保留在明确的边界。

## 状态与模块

- 组件负责展示和局部交互；跨视图状态和动作由 composable 或 store 拥有；跨模块动作由 orchestrator 拥有。
- 状态归属按最小范围选择：组件局部 state、composable、store；能保持局部的状态不得无理由上收。
- service 负责单一外部能力；ViewModel/composable 负责装配状态和消费能力；组件禁止直接绕过正式能力入口。
- store 只持有内存运行态；不得直接拥有 IO、确认框或跨模块编排。
- 组件不得兼管缓存、失效、恢复和跨窗口同步；这些责任必须归明确的状态或动作 owner。
- 领域纯规则与转换保持无副作用；展示投影不得反向修改查询记录或共享只读数据。

## 响应式与输入

- 响应式字段必须保持来源和生命周期清晰；从 store 解构响应式字段使用 `storeToRefs`。
- 表单原文、正式值和提交结果分别表达；解析失败必须保留原文并提供明确错误状态。
- 业务副作用不得隐藏在深度 watch 中；字段动作、保存动作和外部接纳必须经显式入口。
- 组件内快捷键必须经统一分发器；禁止自建全局键盘监听。
- 模板使用的 UI 组件遵循统一注册约定；仅动态渲染场景直接导入对应运行时组件。

## 错误与反馈

- 预期错误由正式 service 或 orchestrator 抛出带稳定语义的错误对象。
- 稳定码、原始诊断、用户文案和结构化位置分别消费；包装错误必须保留来源信息。
- 用户动作只产生一次最终反馈；action 内部不得同时提示并重复抛出同一错误。
- 用户可见错误、警告和确认统一经过反馈入口；禁止直接把 `String(error)` 作为用户文案。
- catch 分支必须提示、记录或执行明确恢复；禁止空 catch。

## 测试

- 原语、解析、归一化、分支分派、保存编排和错误投影必须补充成功与失败行为测试。
- 测试断言行为、输出协议和状态交接；禁止复制生产实现内部步骤作为唯一断言。
- 同构实现使用参数化测试覆盖同类输入；不同语义使用独立测试表达差异。
- 交互测试覆盖输入、焦点、取消、确认、滚动、快捷键和窄窗口行为，只验证公开结果。

## 注释

- 注释使用英文，优先通过改名、拆函数和改类型让代码自解释。
- 只在外部协议、冻结常量、算法不变量、顺序敏感边界和 workaround 处添加注释。
- 禁止复述代码、记录历史过程、保留无追踪目标的 TODO/FIXME 或注释掉的代码。
- JSDoc 只用于公开契约的输入、输出和失败语义。
