# 编辑会话原语

## 定义

编辑会话原语系统以目标身份管理 完整基线快照、草稿、活动输入、保存操作、读取接纳与外部快照 的前端编辑状态机，以及全仓未保存工作的唯一注册表。

## 边界

- dirty 时外部版本只暂存或提示，严禁覆盖；无 dirty 才能采用新 base。
- identity 必须完整包含所属 Mod 与实体或文件目标；切换目标前必须显式处理 dirty。
- 保存基线只允许消费持久化能力返回的实际内容与版本；保存期间的新草稿、活动输入与历史必须保留，外部提示只允许表达其他来源版本。
- 切换或销毁 dirty 配置会话必须经统一确认；确认前不得改变选择、路由或工作区运行态。
- 基线、草稿与待接纳外部快照必须由单次响应式投影共同发布；目标、值、版本凭据与元数据必须属于同一快照。
- 接纳结果必须明确表达 baseline、pending 与 obsolete；保存只允许消费 ready 目标。
- 未保存工作注册表必须响应式登记会话与判定源；配置会话必须聚合草稿与输入差异，CSV 判定源必须聚合全部表的草稿与输入差异；Mod 级消费方只允许查询该注册表。
- 草稿严禁持久化、直接 query、直接 write 或直接写 history。
- 读取取消信号必须随目标票据传入所属 load；query.invalidated 必须结束本次读取消费或保存准备并保留当前草稿。
- 输入集合必须归属编辑目标；控件必须拥有原文、错误状态与取消动作，领域必须拥有形状与转换，会话必须拥有提交顺序与接纳权。

## 链路

### 配置目标编辑

1. ViewModel 为选定实体创建或切换 Draft Session。
2. 表单双向赋值经适配器 setter 提交原语 draft，适配器投影 dirty。
3. 延迟提交控件登记原始输入，输入差异进入所属会话 dirty。
4. 主窗口存活期间按 `modRoot` 在注册表登记 dirty。
5. 保存先逐项提交输入，再捕获独立草稿与版本凭据。
6. 保存成功后以返回实体提交 base；请求期间的新草稿与原始输入保留。

### 外部更新接入

1. 外部读取捕获目标、生命周期、接纳代次与请求序号。
2. 接纳边界复核票据、提交身份与当前目标。
3. 无 dirty 时直接采用新 base。
4. 有 dirty 时外部版本仅暂存并提示可载入。
5. 用户确认放弃后替换 draft、取消所属原始输入并清除暂存。

### 未保存判定

1. 导航、移除 Mod 或关闭工作区等待所属保存句柄。
2. 成功后按最新草稿和输入状态查询未保存注册表。
3. 注册表聚合配置会话登记与 CSV 判定源。
4. 存在未保存工作时触发统一确认。
5. 确认放弃后才释放会话登记并继续销毁。

### 文本撤销栈

1. 文件编辑器以原语家族的撤销栈承载文本前后值。
2. undo/redo 通过栈操作返回目标文本。

## 规范

- dirty 派生必须由原语内部比较产生，严禁外部手工置位。
- 交接必须等待所属保存完成；成功后必须重新判定最新 dirty，取消或失败必须结束当前交接意图并保留编辑面。
- 保存准备必须保留基线已有路径的读取凭据；新建或改名的独立目标必须追加目标凭据，同一物理文件的大小写变化必须消费原凭据。
- 保存准备必须在所属会话持有保存状态后执行；关联表的新版本只允许更新关联凭据，规格值与规格凭据必须保持同一读取来源。
- 保存句柄必须登记进行中保存与待同步状态；导航和关闭必须先重试待同步 receipt，再判定最新 dirty，失败必须保留编辑面。
- 保存必须提交发起保存时的独立草稿快照，严禁提交可变引用。
- 保存操作必须覆盖输入准备、动作结束、独立捕获、写入、基线接纳与后续同步；重复保存必须复用唯一 Promise。
- 保存期间刷新必须合并为一次后续权威读取；同值同版本刷新只允许原子更新元数据，值或版本变化必须推进基线代次。
- 再次保存必须先完成 pendingSynchronization，再于同一保存操作中提交后续输入并捕获新快照。
- 原始输入提交必须按登记顺序执行，每项成功后必须等待消费者投影；失败必须保留原文、定位字段并以 `commit-field-inputs` 动作上抛一次错误。
- 同步失败必须保留实际写盘快照与 receipt；重试必须消费该记录，严禁重复写入已完成的保存。
- 字段删除只允许取消对应稳定身份的输入子树；明确基线替换必须取消所属集合输入。
- 异步字段与资源选择必须捕获所属输入或编辑上下文；外部基线、目标交接与释放必须撤销其结果和错误接纳权，本地保存必须保留编辑连续性。
- 撤销栈 limit 必须由消费方显式设置，原语不自行读配置。
- 未完成字段输入必须参与 dirty、关闭确认和外部版本暂存；本地提交、保存、明确基线交接与释放必须撤销较早读取的值、错误与 loading 接纳权。
- 本地保存必须保留同一会话历史；目标加载、外部基线接纳与重置必须共同清理历史、活动动作、选择和预览。
- 注入的相等比较与克隆必须覆盖全部业务值形态。
- 注册表严禁暴露内部会话结构，只暴露按 `modRoot` 的判定与登记能力。
- 目标必须捕获 sessionId、modRoot、实体种类、ID 与实际路径；保存必须消费捕获目标，重命名必须在同一会话交接目标并保留后续输入。
- 自有身份事务推进基线时必须保留编辑连续性；外部身份交接必须清理旧快照历史，同时必须保留确认后的草稿与活动输入。
- 表单双向绑定必须经唯一适配器 setter 提交 draft，严禁直接替换投影状态或以深度 watch 同步业务副作用。
- 输入取消、目标变化与集合释放必须撤销当前提交接纳权；卸载必须解除登记，销毁会话必须释放集合与目标身份。

## 陷阱

- dirty 时直接应用外部 base 会丢失未保存输入。
- 以 prop 变化直接覆盖 draft 会把外部刷新当成用户输入。
- 保存后无条件提交 base 会把过期快照当作最新草稿。
- 各模块自建 dirty 判定并集会让关闭确认结果互相矛盾。
- 撤销栈保存可变引用会让回放读到被编辑污染的值。
